# ByteBunch • Lab — сайт и панель управления

Код сайта `lab.bytebunch.ru` и панели `lab.bytebunch.ru/admin/`. Структура повторяет папку хостинга
`/home/a1314927/domains/bytebunch.ru/`:

```
private/                      вне public_html — из браузера не открыть
  config.php                  ключ игры и ключ статистики Sionika        (в git не хранится)
  lab/
    config.sample.php         образец настроек панели → скопировать в config.php
    config.php                база данных панели                          (в git не хранится)
    app/                      код панели
    data/                     загруженные HTML-проекты, выпуск Sionika   (создаётся сам, в git не хранится)
public_html/
  lab/                        lab.bytebunch.ru
    index.php                 главная: новости и эксперименты берутся из базы, без базы — запасной HTML
    admin/                    панель
    news/                     новости: news/ и news/<адрес>
    p/                        HTML-проекты: p/<адрес>/
    api/                      API для скриптов
    media/                    картинки из постов
  sionika/                    sionika.bytebunch.ru — проверка обновлений приложения
  game/                       game.bytebunch.ru
```

## Установка

1. **PHP 7.4 или новее** (лучше 8.x) — версия выбирается в панели Спринтхоста для сайта.
2. **База**: «Базы данных» → «Добавить базу данных». Запишите имя, пользователя и пароль.
3. **Файлы**: загрузите содержимое архива в `domains/bytebunch.ru/` поверх существующих файлов.
   Проверьте, что загрузились файлы `.htaccess` в `lab/news/`, `lab/p/`, `lab/api/`, `lab/media/` —
   некоторые FTP-клиенты скрывают файлы с точкой.
4. **Настройки**: скопируйте `private/lab/config.sample.php` в `private/lab/config.php` и впишите данные базы.
5. Откройте **https://lab.bytebunch.ru/admin/** — панель создаст таблицы, перенесёт текущие новости
   и попросит придумать логин и пароль. Для подтверждения нужен пароль базы из `config.php`.
6. В «Безопасности» включите **вход по коду из приложения**.

## Что умеет панель

| Раздел | Что делает |
|---|---|
| Обзор | счётчики, предупреждения о защите, последние изменения |
| Посты | новости: черновик/опубликован, главная новость, дата или метка «скоро», текст в простой разметке, картинки, обложка. Пост с текстом получает страницу `news/<адрес>`, без текста — ведёт по ссылке |
| Проекты | загрузка `.html` или `.zip`; доступ «всем», «по ключу» (секретная ссылка) или «только мне» (временная ссылка на 12 часов); новый ключ одной кнопкой; встраивание в пост `{{project:адрес}}` |
| Sionika | выпуск версии для проверки обновлений (раньше правился `sionika/index.php`) и статистика запусков |
| Безопасность | пароль, вход по коду (TOTP), активные сессии, API-ключи, журнал действий |

## Как устроена защита

- Пароль хранится хешем Argon2id (или bcrypt). Не короче 12 символов.
- После 8 неверных попыток с одного IP вход закрывается на 15 минут; для одного логина — после 25 с любых IP.
- Вход по коду из приложения (Google Authenticator, Яндекс Ключ, Aegis…). Один код дважды не принимается.
- Сессия — случайный токен в cookie `__Host-bblab` (HttpOnly, Secure, SameSite=Strict); в базе только его SHA-256.
  Сутки без действий или 14 дней — и сессия заканчивается.
- Каждая форма с CSRF-токеном и проверкой Origin. Политика CSP запрещает чужие и встроенные скрипты в панели.
- Панель работает только по HTTPS (`require_https` в config.php).
- HTML-проекты лежат вне `public_html` и отдаются через `p/index.php`. Из архивов не берутся `.php`, `.htaccess`,
  скрытые файлы и пути с `..`. Без ключа ответ — «страницы нет». По умолчанию проект открывается в песочнице
  (CSP sandbox): его скрипты не видят cookie сайта и не могут обратиться к панели.
- Картинки из постов проверяются по содержимому; у JPEG удаляются EXIF-данные (координаты съёмки).
- API-ключи хранятся только отпечатком SHA-256, их можно отозвать.

**Забыли пароль или потеряли телефон** — на странице входа «Забыли пароль?»: понадобится пароль базы из `config.php`.

## API для скриптов

Ключ создаётся в «Безопасность» → «API-ключи».

```sh
KEY=bbk_xxxxxxxx_...

# загрузить или обновить проект (по ключу, в песочнице)
curl -H "Authorization: Bearer $KEY" \
     -F slug=aria-bench -F "title=Бенчмарк Aria" -F visibility=key -F file=@bench.html \
     "https://lab.bytebunch.ru/api/?do=project"

# опубликовать пост
curl -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
     -d '{"title":"*Aria* 0.7","summary":"Коротко","body":"## Что нового\n\nТекст.","status":"published","featured":true}' \
     "https://lab.bytebunch.ru/api/?do=post"
```

Остальные запросы (`ping`, `projects`, `posts`) описаны в начале `public_html/lab/api/index.php`.
Если хостинг не передаёт заголовок `Authorization`, присылайте ключ в `X-Api-Key`.
